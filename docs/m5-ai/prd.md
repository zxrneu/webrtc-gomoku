| 项 | 内容 |
|---|---|
| 语言 | 中文 |
| 编程语言 | TypeScript strict（React 19 + CSS Modules + Vitest），引擎落在 `packages/core` |
| 项目名称 | `gomoku_ai` |
| 作者 | 许清楚（Xu）· 产品经理 |
| 状态 | 待评审（架构师 / 工程师 / QA 会签） |

| 原始需求复述 | 「帮我开发最强人机」——在现有 P2P 联机之外新增**本地人机对战**，打开页面即可下棋；AI 必须真的强（会算杀、会防活三/冲四、不犯低级错误），引擎放 core、零 IO、可注入时间源、可毫秒级无网单测，不引入重型第三方 AI 依赖。 |

---

## 1. 产品目标

**一句话目标**：让用户在不连接任何对手、不依赖信令服务器的情况下，打开页面就能和「一个真正会算杀、不会送棋」的 AI 下完整一局。

### 成功标准（3 条，均可自动验收）

| # | 标准 | 目标值 | 验收方式 |
|---|---|---|---|
| S1 | **棋力可信** | 固定 20 题战术基准集（一步成五 ×4、堵对方成五 ×4、活三防守 ×4、双三/双四识别 ×4、三步内 VCF 连杀 ×4），最强档 **20/20** 命中；简单档 ≥10/20 | `packages/core/test` 内固化局面，`pnpm test` 断言 AI 返回值 ∈ 标准答案集 |
| S2 | **思考不卡** | 单步耗时 **P95 ≤ 1000ms、最坏 ≤ 1500ms**（中局 ≥30 手）；一次对局中主线程 `longtask`(>100ms) 数量 **= 0** | 单测用注入时间源测「节点预算收敛」；浏览器侧 PerformanceObserver 采样 |
| S3 | **零负担接入** | 人机模式首屏**新增网络请求数 = 0**（断网可用）；打包体积增量 **≤ 30KB min / ≤ 10KB gzip**；`pnpm test` 新增用例总耗时 **< 1s** | DevTools Network（Offline 勾选仍可开局）；`vite build` 前后对比产物；`pnpm test` 计时 |

## 2. 用户故事

| # | 角色 | 故事 | 验收要点 |
|---|---|---|---|
| US-1 | 首次进入的访客 | 作为只想随便下两盘的人，我想打开页面直接点「人机对战」就开棋，不用管房间号/二维码，以便零门槛试玩 | 断网状态下点击 → ≤1s 内进入可落子状态；全程无错误提示 |
| US-2 | 挑战者 | 作为想认真练棋的人，我想选择执黑先手或执白后手、并选择难度，以便按自己水平匹配对手 | 执白时 AI 自动完成第一手；难度切换在下一局生效，不打断当前局 |
| US-3 | 等待中的人 | 作为玩家，我落子后要能明确看到「AI 正在思考」，且此时点棋盘不产生任何落子，以便不误触、不怀疑卡死 | 出现 thinking 指示；思考期点击棋盘 0 次状态变更；指示消失后 AI 子已落下 |
| US-4 | 下错棋的人 | 作为悔棋的玩家，我想一次撤回「我 + AI」各一步、直接回到我该落子的状态，以便重想一手 | 悔棋后 `moves` 减 2 且 `currentColor === 我的颜色`；我还没落过子时按钮禁用 |
| US-5 | 想再来一局的人 | 作为玩家，我想一键重开且保留我的先手/难度设置，以便连续练习 | 重开后 `moves = []`、先后手与难度不变 |
| US-6 | 联机中的人 | 作为正在联机对局的人，我想切去人机试一手再切回来，且回来时联机棋局原样还在，以便不丢正在进行的一局 | 往返切换后联机侧 `moves` 序列逐手一致、连接不中断 |

## 3. 需求池

### P0（Must have，缺一不可上线）

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-1 | **模式入口与切换**：顶部/侧栏提供「联机对战 ↔ 人机对战」切换 | 切换为纯前端视图态；**联机对局数据（`moves`/颜色/连接）在切换中零变更**（US-6 可回归）；切换不触发任何 socket 重连或断开 |
| P0-2 | **人机模式零连接**：不建 WS、不建 PeerConnection、不依赖信令 | DevTools Offline 下可完整下完一局；Network 面板无 ws/wss 请求 |
| P0-3 | **执子可选**：玩家可选执黑（先手）或执白（后手） | 选执白后进入对局，AI 立即完成黑方第一手；玩家首次点击即为白子 |
| P0-4 | **思考状态可见 + 禁落子**：AI 回合显示 thinking 指示，期间棋盘点击被忽略 | thinking 期间连点 10 次棋盘：`moves` 长度不变；悔棋/重开按钮处于禁用态；指示消失后 AI 落子恰好 1 步 |
| P0-5 | **悔棋语义**：一次退两步（AI + 我），回到我方回合；无可悔时禁用 | 见 US-4；`moves.length < 2` 或我方棋数为 0 时按钮 disabled + toast |
| P0-6 | **重开与结果判定**：重开清盘保留设置；胜负/平局判定**复用 core 的 `applyMove` 返回值**，前端不另写判定 | 五连/长连/平局三类结局文案正确；web 层无自研胜负逻辑（代码审查项） |
| P0-7 | **强度基线（战术正确性）**：必须识别「我方一步成五 → 直接成五」「对方一步成五 → 必堵」「双三/双四威胁」 | 20 题基准集（S1）最强档 20/20；且**不允许**出现「对方已有活三却去别处发展」这类送棋 |
| P0-8 | **算杀能力**：支持必胜连杀搜索（三步内 VCF 类连杀必须找到） | 基准集 4 道连杀题全中；找到杀棋时耗时 ≤ 1s |
| P0-9 | **开局策略**：空盘时 AI 执黑首手固定天元（H8）；AI 执白时在中心 3×3 内固定应答（策略显式、可复现） | 空盘执黑 100% 落 (7,7)；玩家首手落 (7,7) 时 AI 白子落在中心 3×3 内；同输入必同输出（禁随机） |
| P0-10 | **引擎归位 core**：搜索/评估/开局策略全部为 core 纯函数，零 DOM/零 IO，时间源与随机源（如有）通过参数注入 | `packages/core` 无 `Date`/`performance`/`window` 直读；每个新导出函数有对应用例（AGENTS §1 铁律 5）；单测不启动浏览器 |
| P0-11 | **零重型依赖**：不引入任何第三方 AI/棋力库 | `package.json` 依赖零新增（P0-11 与 S3 体积预算联动） |

### P1（Should have）

| ID | 需求 | 验收标准 |
|---|---|---|
| P1-1 | **3 档难度**（简单 / 普通 / 最强），用**同一套代码 + 不同思考时间预算与搜索深度参数**区分 | 三档共用引擎；参数集中在单一配置对象；同一局面三档可产出不同落点 |
| P1-2 | **主线程友好**：分片让出（可中断搜索）或 Worker 化，使 S2 的 longtask=0 达标 | PerformanceObserver 采样一局，longtask 计数 = 0 |
| P1-3 | **难度/先后手持久化**：localStorage 记住上次选择 | 刷新后设置保持；首次访问默认「最强 + 执黑」 |
| P1-4 | **AI 落子高亮**：AI 最后一手用与玩家不同的标记区分 | 视觉可辨（颜色/描边），不影响既有「最后一手」标记逻辑 |

### P2（Nice to have）

| ID | 需求 | 验收标准 |
|---|---|---|
| P2-1 | **提示（Hint）**：玩家回合点提示，给出推荐落点（不自动落子） | 提示耗时 ≤ 1s；提示点不计入 `moves` |
| P2-2 | **形势评估条**：显示当前优劣势指示 | 仅展示，不影响规则与胜负 |
| P2-3 | **开局库/定式**：常见开局前 4 手预置 | 命中库时思考耗时 ≈ 0 |

## 4. 难度设计

**结论：P0 只交付 1 档「最强」；P1 扩为 3 档，且必须是「一套引擎 + 三组参数」，禁止三套代码（违反 AGENTS §2 开闭原则）。**

| 档位 | 思考时间预算 | 搜索深度上限 | 定位 | 期望表现 |
|---|---|---|---|---|
| 简单 | 200ms | 浅（≤2 层） | 新手能赢 | 会成五、会堵成五；漏防活三 |
| 普通 | 500ms | 中（≤4 层） | 有来有回 | 会防活三；偶尔漏算双威胁 |
| **最强（P0 默认）** | **1000ms** | 深（迭代加深至预算耗尽） | 认真下也难赢 | 20/20 基准集；不送棋；三步内连杀必中 |

参数约束：三档参数集中在 core 内一个只读配置对象，**不散落在 UI 或调用点**；UI 只传档位标识。

## 5. UI 设计稿（文字 + 结构）

```
┌──────────────────────────────────────────────────────────────┐
│ Header: 五子棋   [● 联机对战 | ○ 人机对战]        ← P0-1 切换 │
├───────────────────────────────────────┬──────────────────────┤
│                                       │  对局信息区           │
│                                       │  ┌────────────────┐  │
│           Canvas 棋盘                 │  │ 人机对战        │  │
│      （复用现有 Board.tsx）            │  │ 难度：最强 ▾    │  │
│                                       │  │ 我：黑（先手）  │  │
│      ┌─────────────────────┐          │  │ AI：白          │  │
│      │  ● AI 正在思考…     │ ← P0-4   │  └────────────────┘  │
│      └─────────────────────┘          │  [悔棋] [重开]       │
│                                       │  （思考中禁用）       │
└───────────────────────────────────────┴──────────────────────┘
```

1. **入口位置**：Header 右侧模式切换（分段控件，两项），默认停在「联机对战」以保持老用户路径不变。
2. **人机面板**：切到人机后，右侧原「邀请对局」面板整体替换为「人机设置卡」——难度下拉（P1）、执子切换（执黑/执白）、开始新局；聊天区在人机模式下隐藏。
3. **AI 思考反馈**：棋盘内轻量浮层条 + 侧栏对局信息区文案「AI 正在思考…」双处提示；无全屏遮罩（避免遮挡棋局）；思考期棋盘 `cursor: not-allowed`。
4. **对局信息区**：复用 `GameStatus` 的位置与样式，人机模式下黑/白名称改为「我 / AI（最强）」，并额外显示「人机对战」标签，与联机态的传输链路指示器互斥。
5. **切换回联机**：若联机局正在进行，切回时**直接恢复原棋盘**（不弹确认，因数据未被破坏）；若人机局正在进行，则保留其状态，再次切回人机时原样恢复。

## 6. 非功能需求

| 类别 | 要求 | 验收 |
|---|---|---|
| 性能 | 最强档单步 P95 ≤ 1s、最坏 ≤ 1.5s；搜索必须**可被时间预算中断**并返回当前最优解 | 注入假时间源的单测断言「预算耗尽即返回」 |
| 主线程 | 单次阻塞 **≤ 100ms**；理想路径：`setThinking → 渲染 → 让出 → 搜索（分片）→ 落子`，保证 thinking 指示先上屏 | longtask 计数 = 0（P1-2） |
| 可测试性 | 引擎纯函数；时间源、调度器（让出方式）均通过参数注入；同输入必同输出（禁 `Math.random`） | core 用例毫秒级全绿；`pnpm test` 新增部分 < 1s |
| 体积 | 增量 ≤ 30KB min / ≤ 10KB gzip（当前单文件产物 ~492KB，AI 引擎必须手写、零依赖） | build 前后对比 |
| 可访问性 | thinking 状态需有 `aria-live` 文本（读屏可感知）；禁落子期 `aria-disabled` | 手工检查 |
| 兼容性 | 不新增浏览器 API 依赖（不强制要求 Worker/SharedArrayBuffer） | 无新 feature detection 分支 |
| 不回归 | 联机全流程、`pnpm build && pnpm test`（+ 改 web 后 `pnpm test:e2e`）全绿 | CI |

## 7. 待确认问题（需用户/主理人拍板）

| # | 问题 | 我的推荐 | 理由 |
|---|---|---|---|
| Q1 | 「最强」档默认思考 **1s 还是 2s**？ | **1s**（P1 允许在设置里切到 2s） | 1.5s 以上用户会怀疑卡死；1s 配合迭代加深已足够覆盖三步内连杀 |
| Q2 | 是否需要 **Web Worker**？ | **P0 不用 Worker**，用「分片让出 + 时间预算中断」；Worker 列为 P1 备选 | 本仓库用 `vite-plugin-singlefile` 打单文件，inline Worker 有构建兼容风险；core 保持纯函数也能满足 longtask 指标 |
| Q3 | 人机模式悔棋是否**无限制**？ | **无限制、不计次数、无惩罚**（单机练习场景，无需竞技公平性） | 加限制只会增加规则复杂度，无对应收益 |
| Q4 | 联机局进行中切到人机，切回时是否需要**确认弹窗**？ | **不需要**，静默保留并在切回时提示「已恢复你的联机对局」 | 数据未被破坏，弹窗属于多余打断（参考 reconnect PRD 的「提示克制」原则） |
