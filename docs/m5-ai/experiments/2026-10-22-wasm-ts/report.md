## 条件与限制

- 从 15×15 空盘开始，黑棋先行，无禁手，五连及长连获胜。没有提前按分数判胜或把未结束对局计为和棋。
- 直接在 Node 调用网页同一个 createSearchWorkerHandler，双方各有独立策略证书缓存。复用证书时与网页一样直接执行已验证策略，不再调用评分。没有浏览器渲染、Worker 消息传输和定时器等待开销；结果不能代替各设备浏览器中的性能测量。
- 限时两局均为网页 hard 默认配置：每手 3000ms 搜索预算、maxDepth=16、maxNodes=500000、VCF 节点上限 24000、PNS 节点上限 80000。实际落子耗时包括会话构造和策略导入，并非每手都用满预算。
- 节点对照为 hard、maxDepth=12、常规 maxNodes=8000、VCF=512、PNS=1024，注入恒定时钟以排除墙钟波动。各搜索阶段独立计数，maxNodes 不是所有阶段相加后的总节点限制。
- 顺序运行，先预热双方评分路径，再互换执色。限时对弈会受 JIT、运行顺序和系统负载影响；两局不能建立稳定的强弱排序。
- 当前 Rust/WASM 实现替换方向评分和假设落点评分，双方继续共用 TS 搜索、算杀和证明校验；本次没有比较离线 Rust gomoku-solver。

## 校验

全部 292 手均通过合法落子与输入未被搜索修改的检查。每份胜利证书在当时局面独立复验；全部对局重新播放至合法终局，并再次按四方向计数确认获胜方确实成五。固定节点两局的全部 66 手落点、节点数、深度、分数、终止原因和证明状态逐手一致。上述固定节点配置下双方执黑均输；本次限时两局黑胜不能解释为对任意后手都能获胜的保证。
