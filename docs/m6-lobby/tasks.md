## 已复现、待修复

| 编号 | 优先级 / 范围 | 问题 | 验收条件 |
| --- | --- | --- | --- |
| L-01 | P1 / Node | 新连接恢复座位后，旧 socket 的 leave 会销毁座位 | 旧物理连接永久撤权；leave、ping、create/join 均不能影响新连接；有效新 token 仍能恢复 |
| L-02 | P2 / Node | 缺少全部大厅请求的突发限流 | 单连接连续 100 个列表请求被限流，其他连接仍可用；明确窗口与阈值，保留正常查询 |
| L-03 | P2 / 前端 | 第三个窗口被拒绝后，5 秒查询覆盖配额提示 | 未成功进入时停止无效查询，保留原始拒绝原因；关闭一个旧窗口后可重试进入 |
| L-04 | P2 / 前端 | window.open 复制 sessionStorage，误把新窗口当刷新 | 新窗口具有独立身份，原窗口继续可用；真正刷新仍恢复本窗口座位，不能破坏两会话配额 |

先写失败单测再实现；使用[协议扩展测试](../../test/lobby-protocol.e2e.js)和[窗口边界脚本](../../test/lobby-edge.e2e.js)验证实际行为。两个脚本在对应缺陷尚未修复时会返回非零状态；不据此宣称默认回归失败，也不把复现结果改为通过。

## 带宽优化（待实现）

- [ ] 名册/房间的搜索、分页与统计采用 HTTP 按需读取；保留会话校验、私密房过滤与限流。接口与缓存版本约定在实现前确定，不把候选 URL 写成已有端点。
- [ ] WebSocket 发送定向结果和短小的变更通知；公共列表按订阅范围推送，版本缺号或重连后重新查询。邀请、匹配、房内离线/恢复保持即时反馈。
- [ ] 后台页面停止无用刷新，回到前台后补查；Node 与 Rust 明确同一发布契约并共享行为验收。
- [ ] 同规格重测静止大厅、持续状态变更、100 人断线波、慢消费者、分页与后台切换。记录端到端查询延迟、消息正文与实际出口、CPU/内存和连接回收，不能只检查 `/healthz`。

通过条件：持续变更下不回退为向所有人每秒推送整份列表，100Mbps 出口预算内保留余量，无版本乱序和私密数据泄漏。压测先在隔离实例执行，不把配置上限当作容量结论。
