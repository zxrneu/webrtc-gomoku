## 带宽优化（待实现）

- [ ] 名册/房间的搜索、分页与统计采用 HTTP 按需读取；保留会话校验、私密房过滤与限流。接口与缓存版本约定在实现前确定，不把候选 URL 写成已有端点。
- [ ] WebSocket 发送定向结果和短小的变更通知；公共列表按订阅范围推送，版本缺号或重连后重新查询。邀请、匹配、房内离线/恢复保持即时反馈。
- [ ] 后台页面停止无用刷新，回到前台后补查；Node 与 Rust 明确同一发布契约并共享行为验收。
- [ ] 同规格重测静止大厅、持续状态变更、100 人断线波、慢消费者、分页与后台切换。记录端到端查询延迟、消息正文与实际出口、CPU/内存和连接回收，不能只检查 `/healthz`。

通过条件：持续变更下不回退为向所有人每秒推送整份列表，100Mbps 出口预算内保留余量，无版本乱序和私密数据泄漏。压测先在隔离实例执行，不把配置上限当作容量结论。
