# 聊天、图片、文件与语音消息

先通过大厅、房间号或手动连接码与对手建立连接，再打开“聊天”。这里的语音是录制后发送的消息；实时语音通话和视频通话仍属于后续规划。

## 发送与接收

| 操作 | 步骤 |
| --- | --- |
| 文字 | 输入文字后点击“发送”；每条最多 100 字符 |
| 图片 | 点击“发送图片”，选择一张图片；收到后点击缩略图查看，使用浏览器保存图片 |
| 文件 | 点击“发送文件”选择文件；完成后点击文件卡片的“下载”保存到本机 |
| 语音 | 点击“语音消息”，首次允许麦克风；录制中点击“发送”结束并发送，或点击“取消”丢弃 |
| 播放语音 | 点击消息气泡内音频控件的播放按钮；音量、进度由浏览器音频控件提供 |
| 取消传输 | 发送方或接收方点击进度卡片中的“取消”；取消后需要重新选择文件发送 |

语音到达 60 秒会自动结束并发送，不提供发送前试听。图片和文件在录音期间不能选择；录音失败不影响棋盘和文字聊天。入口文案和布局以当前客户端为准。

文件传输显示已传字节、百分比和状态；当前没有传输速率、剩余时间、拖拽发送、断点续传或服务器离线投递。

## 限制与确认

| 项目 | 当前规则 |
| --- | --- |
| 单个附件 | 最大 500 MiB；超过时拒绝发送和接收 |
| 自动接收 | 小于 50 MiB 的附件自动接收；达到 50 MiB 需要接收方确认 |
| 接收确认 | 等待约 60 秒仍未确认时传输失败；大文件应先告知对方 |
| 大文件提示 | 超过 100 MiB 提示网络环境；移动设备仍需考虑内存和网络条件 |
| 数据停滞 | 接收过程中约 15 秒没有新数据，或发送结束后约 15 秒没有完成回执，会失败 |
| 单条语音 | 最长 60 秒；两端均需支持录音能力 |
| 高风险文件 | 双端拒绝 `.exe`、`.bat`、`.cmd`、`.apk`、`.sh`、`.msi`、`.scr`、`.com`、`.vbs`、`.ps1`、`.jar`、`.dll` |
| SVG | 按文件下载处理，不以内嵌图片或同源新页面执行 |

MiB 按 `1024 × 1024` 字节计算。大小、超时和扩展名策略以 [共享媒体规则](../packages/shared/src/media.ts) 为准。附件由浏览器内存缓存和重组，500 MiB 是协议上限，不保证每台手机都能顺利处理到该大小。

## 语音入口不可用时

1. 确认双方已经连接，等待双方能力协商完成；旧客户端可能不支持附件或语音。
2. 双方都使用受信任的 HTTPS。开发机的 localhost 可以录音；普通局域网 HTTP 不能用于录音。
3. 页面提示浏览器不支持时，检查 `getUserMedia` 和 `MediaRecorder` 是否可用，换用系统浏览器复试。
4. 已拒绝权限时，在站点设置和系统设置中允许麦克风，然后刷新页面重新连接。
5. 文件传输失败时，检查对方是否拒绝、取消或离线；恢复连接后重新发送，未完成附件不会自动续传。

证书与权限步骤见 [HTTPS 配置](https.md#6-语音权限与排障)，设备验证范围见[测试与兼容性](testing.md#浏览器与运行方式)。

## 保存、隐私与会话边界

聊天和附件只保存在当前页面内存中，没有聊天历史数据库或云端附件存储。刷新页面后，可能恢复房间和棋谱，但不会恢复聊天、录音或附件下载链接；需要的文件应及时下载。

离开或切换房间、对手正式离开导致会话清空时，旧记录和附件链接被回收。短暂断线时，当前页面已完成的消息可能保留到会话重置，但正在传输的附件会失败，正在录制的语音会取消；旧录音不会自动发给下一位对手。

内容经 WebRTC DataChannel 传输。信令服务处理昵称、房间和连接协商信息；使用 TURN 时，中继会转发 WebRTC 加密流量。“P2P”不代表没有连接元信息，也不提供对手真实身份认证。昵称是临时标识。

实现入口见 [Chat 组件](../packages/web/src/components/Chat/Chat.tsx)、[媒体会话](../packages/web/src/media/useChatMedia.ts)；真实双端验证见 [媒体 E2E](../test/media-real-p2p.e2e.js)。
