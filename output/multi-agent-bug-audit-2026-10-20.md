## 已确认问题

### 1. P1：Node 信令服务可被畸形字段触发进程退出

- 位置：`apps/server/src/server.ts:167-185`。
- 原因：JSON 解析后直接断言协议类型，只检查 `t`；后续对外部字段执行 `String()`，某些合法 JSON 对象会让转换抛错，而该异常不在捕获范围内。
- 影响：未入房连接也能触发，整个 Node 实例退出，影响该实例所有玩家。没有证据表明 Rust 服务存在同一问题。
- 验证：独立本机 Node 子进程接收畸形房间字段后退出，`exitCode=1`，堆栈指向第 185 行，异常为 `Cannot convert object to primitive value`。
- 建议：统一以 `unknown` 接收输入，完成字段类型验证后再分派；非法数据不进行隐式转换。

### 2. P1：旧会话录音可沿新对手的连接发送

- 位置：`packages/web/src/media/useChatMedia.ts:329-333,411-426`；`packages/web/src/App.tsx:483-494`。
- 复现：开始录音 → 换房或对手离开 → 新对手连接 → 停止并发送录音（或达到自动停止时间）。
- 原因：会话清理调用 `failAll()`，但没有取消录音；停止录音使用最新的发送回调和连接。
- 验证：临时 hook 测试执行实际会话重置组合 `failAll()` 和 `revokeAllUrls()` 后停止录音，发送函数仍调用一次。此项为 hook 级验证，没有执行三名真实浏览器玩家的完整录音串房验收。
- 建议：会话结束时取消录音，并为所有异步录音结果绑定会话代际，拒绝跨会话发送。

### 3. P2：原房主离开后，剩余玩家无法接入下一名玩家

- 位置：`packages/shared/src/reconnect/orchestrator.ts:377,515`。
- 复现：A 建房，B 加入；A 离开；C 加入同一房号。
- 原因：B 重新等待时仍为 guest，C 也为 guest；只有 host 会发起 offer。
- 验证：现有 FakeClock/FakeSignal/FakeP2p 复现 `NEGOTIATING guest attached []`；推进 15 秒后 `FAILED ICE_FAILED`。
- 建议：明确房间剩余玩家的协商角色切换契约，并同步服务端座位恢复语义。

### 4. P2：非法 sync 棋谱通过安全解码后仍可抛未捕获异常

- 位置：`packages/shared/src/codec.ts:209-211`；`packages/shared/src/reconnect/sync.ts:40`。
- 原因：仅验证 moves 是数组，未验证每项坐标与颜色；重放直接将非数值坐标传入规则引擎。
- 验证：包含对象坐标的 sync 消息解码返回 `ok:true`，随后重放抛出 `TypeError`，而非按非法棋谱返回拒绝结果。
- 建议：校验棋谱元素结构、整数坐标、边界和颜色后才交给重放。

### 5. P2：未关联请求的悔棋/重开确认也会修改棋盘

- 位置：`packages/web/src/connection/onlineMessages.ts:191-193,206-207`。
- 复现：已有一手棋，本端没有申请重开，对端直接发送 restart-ok。
- 实际：棋盘从一手变为零手；undo-ok 同样无待确认请求校验。
- 验证：临时消息处理器测试确认了上述状态变化。
- 建议：为悔棋和重开建立请求状态，确认必须关联当前会话、当前申请及对应棋局版本。

### 6. P2：悔棋/重开确认发送失败仍单方面提交

- 位置：`packages/web/src/connection/onlineMessages.ts:187,202`。
- 复现：收到申请弹窗 → 通道断开 → 点击同意。
- 原因：先修改棋盘，再发送确认，且忽略发送失败。
- 验证：发送替身返回 false 时，确认悔棋仍使本端从一手变为零手。
- 建议：先校验发送结果；断线或会话改变时使旧申请失效。

### 7. P2：已入房连接恢复另一座位，遗留永久幽灵房间

- 位置：`apps/server/src/server.ts:259-263`。
- 复现：连接先创建 PREV，再携另一座位的合法凭证恢复 ORIG，随后关闭连接。
- 原因：直接覆盖连接身份，没有释放原身份的 membership 和 seat；关闭只处理新身份。
- 验证：两个 membership 同时存在、房间计数为 2；关闭后旧座位的 `offlineSinceMs` 和 `expiresAtMs` 仍为 null，不能通过宽限期扫描回收。
- 建议：拒绝已有房间的连接执行跨身份 resume，或在验证成功后完整迁移并释放原身份资源。

### 8. P2：局域网 HTTP 下录音入口消失且没有原因说明

- 位置：`packages/web/src/media/capabilities.ts:12-21`；`packages/web/src/components/Chat/Chat.tsx:174-185`。
- 用户实际场景：已连接对手，通过局域网 HTTP 地址访问。
- 原因：录音需要浏览器提供 getUserMedia；普通局域网 HTTP 不属于安全来源时该 API 不可用。代码把 audio 能力设为 false，界面直接不渲染按钮。能力满足时按钮也只有 🎤，没有可见文字。
- 浏览器依据：[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。安全来源限制属于浏览器行为；项目问题是缺少可发现的入口及不可用原因提示。
- 建议：提供可见的“录音”标识和不可用原因；局域网 HTTP 明确提示需要 HTTPS。仅显示按钮不能解除浏览器限制。
